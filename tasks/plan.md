# 实施计划：未开通套餐学生的年级体验试用

## 目标

为已完成微信/手机号绑定、但尚未开通正式学习套餐的学生，提供一次 **7 个自然日** 的年级匹配体验。体验不绑定支付、不自动续费；学生应在体验中完成“课程 → 练习 → 结果反馈”的完整闭环。到期后保留学习记录，学生可联系老师由教务明确执行“试用转正”。

本方案沿用现有套餐和有效期授权，不创建第二套内容权限：试用成功时仍创建一条有明确开始、结束日期的套餐授权，因此课程、资料、作业和下载权限继续由既有的 `grantActive` / 学习空间访问逻辑控制。

## 已确认的约束与关键决策

- 仅面向后台已有学生档案、且当前微信登录已绑定到该学生的用户；当前登录逻辑不会为陌生手机号自动建学生档案。
- 体验从用户在首页点击“开始体验”后开始计时，而不是选择年级或登录成功即开始。
- 一个学生在一个学年只能领取一次体验；资格键为 `student_id + academic_year`，不按手机号或微信 OpenID 计算，避免同一学生的多家长重复领取。
- 时长固定为 7 个自然日，包含开始日和结束日；例如 9 月 1 日开始，9 月 7 日 23:59:59 前有效。日期计算和授权校验统一使用服务端 `Asia/Shanghai` 日期。
- 当前 `Package` 必须属于一个年级、一个学科和一个学期，不能跨学科组合学习空间。因此不设置“跨学科默认体验套餐”：同年级只有一个可体验套餐时直接确认；有多个时，在领取动作后让学生选择一个学科/体验套餐，不把选择塞进登录表单。
- V1 不接支付、不自动续费。正式开通必须由有权限的教务在学生详情中明确执行“试用转正”，避免把普通赠送或临时人工授权误记为转化。

## 业务状态与判定

### 体验状态

| 状态 | 服务端判定 | 学生端行为 |
|---|---|---|
| `eligible` | 本学年没有体验记录，且该年级存在至少一个有效体验套餐 | 显示领取入口；多套餐时展示套餐选择 |
| `active` | 存在记录且当天在 `startedAt`、`endsAt` 的闭区间内 | 显示剩余天数、继续学习和正式开通入口 |
| `expiring` | `active` 且剩余不超过 2 天 | 在首页、学习页显示到期提醒 |
| `expired` | 存在记录且结束日早于当天，且未转正 | 保留进度/结果，锁定体验内容，显示联系老师开通 |
| `converted` | 教务通过试用转正动作开通正式套餐 | 不再显示倒计时；按正式套餐继续学习 |
| `unavailable` | 当前年级没有可用体验套餐，或候选套餐不含可学习内容 | 不展示试用入口，沿用联系老师开通提示 |

`active` 与 `expiring` 是展示层状态；持久化记录只保存 `active`、`expired`、`converted`。这样无需定时任务：现有授权会在每次请求时按结束日期自动失效，首页读取时再计算是否临期或到期。

### 资格与领取逻辑

1. 小程序完成已有的微信登录和手机号绑定，获得含当前 `StudentID` 的 token。
2. `GET /api/student/home` 查询当前学生的体验摘要：先读取本学年体验记录，再找同年级、已启用且标记为可体验的套餐。
3. 学生点击“开始 7 天免费体验”。若候选套餐为 1 个，前端直接带该 `packageId`；若为多个，先显示套餐/学科选择，再提交。
4. `POST /api/student/trial/start` 在一个事务内执行：验证登录学生、资格、套餐年级、套餐体验开关及真实内容；写入体验记录；调用现有套餐授权逻辑，起止日为当天和当天加 6 日。
5. 重复点击或网络重试：若已有活跃体验，返回同一条体验状态与入口，不再新建授权；已到期或已转正则拒绝再次领取。
6. 成功后返回首门课程 ID（没有课程时返回空），小程序优先跳转课程详情；无课程时回学习页并提示体验内容正在准备，后台不允许将这种套餐标记为可体验。

### 到期与转正逻辑

1. 到期不执行删除，也不清空进度、提交记录、收藏或反馈；仅因授权结束而不能继续读取受保护内容。
2. `student/home` 和 `student/study` 都返回体验摘要，前端不再仅用 `openedPackages.length` 判断“已开通”，否则体验套餐会被误显示成正式套餐。
3. 教务在学生详情查看体验记录后，选择正式套餐和有效期，调用显式“试用转正”接口。该接口原子地创建/延长正式套餐授权，并把体验记录更新为 `converted`、保存正式套餐 ID 与转正时间。
4. 若正式套餐和体验套餐相同，复用现有授权更新有效期；若不同，则两条授权可并存，体验授权到期后自然失效。不得通过“发现学生有其他套餐”自动改为 `converted`。

## 数据和接口契约

### 套餐配置

在 `Package` / `PackageUpsertRequest` 中增加 `trialEnabled: boolean`，默认 `false`。

启用体验套餐时后端必须校验：套餐已启用、至少开放 `course` 与 `question`、且在关联学习空间中至少有一门对学生可见的课程和一份可完成的练习。若不满足，保存失败并说明缺少的内容；关闭体验开关不影响已开始体验的学生，已开始体验继续至原结束日。

### 体验记录

新增 `student_trial_records`，字段建议如下：

| 字段 | 说明 |
|---|---|
| `external_id` | 稳定业务 ID，供内存快照与 MySQL 增量同步 |
| `student_id`、`academic_year` | 联合唯一，保证每学年一次资格 |
| `package_id` | 学生实际领取的体验套餐 |
| `started_at`、`ends_at` | 体验有效期，结束日包含在内 |
| `status` | `active`、`expired`、`converted` |
| `converted_package_id`、`converted_at` | 仅显式转正时写入 |
| `created_at`、`updated_at` | 审计与排障 |

不在 `student_package_grants` 上增加“试用/正式”推断字段：体验记录才是一次性资格和转正归因的权威来源，现有授权表继续只负责内容访问。

### 学生接口

`GET /api/student/home` 在既有响应中增加：

```json
{
  "trial": {
    "state": "eligible",
    "days": 7,
    "endsAt": "",
    "remainingDays": 0,
    "options": [{ "packageId": "pkg-...", "packageName": "五年级英语体验", "subject": "英语" }]
  }
}
```

`POST /api/student/trial/start`

```json
{ "packageId": "pkg-g05-english-trial" }
```

仅允许学生本人 token 调用。成功返回最新 `trial` 摘要和 `firstCourseId`；重复领取中的同一活跃体验返回成功且不新增记录。

### 教务接口

- `GET /api/students/:id/trials`：读取学生体验历史。
- `POST /api/students/:id/trials/:trialId/convert`：传入正式 `packageId`、可选开始/结束日期；仅 `ops_staff`、`campus_admin`、`super_admin` 可调用。

全部接口保持项目统一的 `{ code, message, data }` 响应结构；写入操作应继续通过 `X-Operator-ID`、`X-Operator-Name` 留痕。

## 页面与文案流程

### 首次领取

```text
登录绑定成功 → 首页载入 trial=eligible
  → 展示“领取 7 天免费体验”卡片
  → 点击后（候选多于一个时先选择学科）
  → 确认弹窗：体验至 X 月 X 日、不自动扣费、可学习的内容
  → 开始体验
  → 进入第一节课程 → 完成练习 → 查看结果反馈
```

首页卡片文案：`完成一节课程和一次练习，看看适不适合你。免费体验 7 天，不会自动扣费。`

### 体验中 / 临期 / 到期

```text
active    → 首页卡片“还可体验 N 天”，主按钮“继续学习”
expiring  → 额外提示“体验将在 X 月 X 日结束”，按钮“联系老师开通”
expired   → 保留已完成内容和结果摘要；课程入口显示“体验已结束”
converted → 移除试用倒计时，展示正式套餐学习内容
```

V1 的“联系老师开通”只展示明确的联系指引，不伪造支付按钮；后续若接入支付，必须重新设计价格、自动续费和取消说明。

## 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 体验套餐只有内容类型配置、没有真实课程或练习 | 学生领到空体验 | 在启用体验开关和开始体验时双重校验真实内容 |
| 多家长或请求重试重复领取 | 权益和统计失真 | 以 `student_id + academic_year` 唯一约束，开始接口幂等 |
| 用本机时间计算导致跨日误差 | 多一天或少一天 | 服务端统一 `Asia/Shanghai` 日期，结束日闭区间校验 |
| 手动赠送被误判为转正 | 转化统计错误 | 仅显式“试用转正”接口改变 `converted` |
| 体验套餐被当成正式套餐 | 首页空状态和引导错误 | 学生端以 `trial.state` 优先渲染，不只看 `openedPackages` |

## 不在本期范围

- 自动续费、支付绑卡、优惠券、裂变邀请码。
- 多次复领、按设备或手机号限制资格。
- 未订阅消息授权时的到期推送；V1 在用户打开小程序时提示，后续再接入订阅消息。
- 单独的数据看板和 A/B 实验；先保留体验记录与转正字段，待有真实使用量后再定义指标。
