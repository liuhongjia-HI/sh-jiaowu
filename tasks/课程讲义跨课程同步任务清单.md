# 课程讲义跨课程同步任务清单

## 1. 目标与第一版范围

业务目标：S 课程上传或替换资料后，操作人可以将本次成功上传的资料同步到已存在的 S+ / H / H+ 课程的指定课节，减少重复上传。

以下为建议实施基线，不代表已经开发完成：

- 单向、手动触发；每次明确选择目标课程。课程名称中的 S / S+ / H / H+ 只供人识别，不作为自动绑定依据。
- 同步对象为“课程讲义”模块中的文件资料，标签以当前代码支持值为准；不扩展到课后练习模块的题目、提交、成绩和截止时间。
- 同步标题、文件、标签和下载设置；目标资料沿用现有上传逻辑发布，操作前明确展示会发布/替换哪些资料。
- 已有相同“课程 + 课节 + 标签”的资料时，展示覆盖清单，确认后替换；保留目标资料 ID、浏览数和排序。不删除目标课节的其他标签资料。
- 文件复用同一 `fileId`，课程资料记录各自独立；日后修改源资料不会自动联动。
- 不复制整门课程，不自动新增/重排目录，不自动开通学生权限，不做双向同步、后台自动同步或全课程历史补齐。
- 第一版不新增复制关系表。目录匹配只提供建议，无法唯一匹配时由操作人选择目标课节。

## 3. 操作流程与一致性规则

1. 操作人在源课程、源课节上传一份或多份资料。
2. 展示逐文件结果；有成功文件时提供“同步到其他课程”。有失败文件时明确说明这些文件不在同步范围。
3. 勾选有权限的目标课程，并逐个确认目标课节。
4. 后端预检查，列出每个目标课节将新增/替换的资料及发布影响。
5. 操作人确认后执行一次同步。提交时重新检查权限、课节和资料状态，防止预览后数据发生变化。
6. 一次同步请求中的全部目标记录在同一事务内成功或回滚；源课程上传不属于该事务。
7. 成功后展示各课程新增/替换数量；失败保留选择，支持修正后重试。

不勾选任何目标课程时只执行原上传流程。同批次中重复上传同一标签，以源课节最终有效的资料为准，不同步已被替换的旧文件。

## 4. 实施任务

### A. 契约与基础规则

- [x] **T01：确定接口和前端类型契约**（无依赖）
  - 新增 `POST /api/materials/sync-preview` 和 `POST /api/materials/sync`，在静态路径与 `:id` 路由共存时检查路由匹配。
  - 请求包含 `sourceCourseId`、`sourceLessonId`、去重后的 `materialIds`、`targets: [{ courseId, lessonId }]`。
  - 预检查返回目标名称/课节、逐资料的 `create` / `replace` 动作、原目标资料信息、不可执行原因，以及提交时用于检测变化的快照标识。
  - 执行请求携带预检查快照；返回逐目标的新增数、替换数和目标资料 ID。
  - 继续使用 `{ code, message, data }`，操作者沿用 `X-Operator-ID`、`X-Operator-Name` 和现有认证机制。
  - 位置：`content_entity.go`、`web/src/types/starline.ts`、`docs/API.md`。
  - 验收：旧上传接口和调用类型不变；新契约能表达多文件、多目标、覆盖和预检查失效。

- [x] **T02：实现目标候选与课节推荐规则**（依赖 T01）
  - 利用现有课程/学习空间数据，筛选同年级、同学科、同学期阶段的候选，排除源课程；不从课程名猜测系列关系。
  - 候选显示完整课程名、阶段和状态；最终仍需后端校验可写权限。
  - 仅完整目录路径中节点类型及非空名称一致、且目标唯一时推荐课节；不凭单个标题或序号自动绑定。
  - 路径含空名、多个匹配或无匹配时要求手动选择；目标必须是可挂资料的叶子节点，兼容浅层目录。
  - 位置：`web/src/utils/curriculum.ts`、`ResourceDialogs.tsx`，后端复用课程和叶子节点校验。
  - 验收：同名不同章不误选；已改名或空名目录可手动处理；没有目标课节时不能执行。

- [x] **T03：实现后端同步预检查**（依赖 T01）
  - 校验源课程、源课节、资料归属、源读取权限及资料上传权限；所有源资料必须属于指定源课节。
  - 校验所有目标课程的写入范围、年级学科与阶段、目标课节归属及叶子节点资格。
  - 拒绝源课程作为目标、同一目标课程出现多次、空目标、缺失文件资产和空标签；对资料 ID 去重。
  - 复用同课节同标签定位逻辑；发现历史多条记录占用同一标签时返回冲突，不随意覆盖其中一条。
  - 生成新增/替换清单和快照；无权限对象仅返回通用错误，不泄露资料详情。
  - 位置：新增 `memory_material_sync.go`，复用 `memory_content.go` 中权限/目录/标签规则。
  - 验收：预检查不产生写入、预览任务或通知；非法请求无法绕过前端校验。

### B. 后端同步执行

- [x] **T04：实现单目标资料新增与替换**（依赖 T03）
  - 由源资料生成目标记录，重算目标课程、学习空间、课节及目录路径。
  - 复用文件资产及预览信息，不重复上传、不重复创建同文件转换任务。
  - 新增记录生成独立 ID；替换保留目标 ID、浏览数及排序；目标上传人记录本次操作者。
  - 仅变更本次选择的标签，不清空其他资料，不复制源浏览记录。
  - 抽取最小必要的写入复用点，避免直接逐次调用会单独持久化、发通知的公开上传方法。
  - 验收：源与目标记录 ID 不同而 `fileId` 相同；替换不增加同标签记录数。

- [x] **T05：实现整批事务、变化检测与重复提交保护**（依赖 T04）
  - 基于 `persistentMutation` 将全部目标资料、审计与通知纳入一次提交；内存模式也避免失败后留下半批结果。
  - 在写入锁/事务边界内重做校验；源文件、目标课节或被覆盖资料自预检查后变化时，要求刷新预检查。
  - 重复点击或网络超时后重试不能产生重复资料、通知；可在快照校验中识别“已达到本次预期结果”并返回已完成。
  - 验收：第二个目标失败时第一个目标也不落库；源上传仍保留；重复提交不重复产生副作用。

- [x] **T06：接入 API、持久化及审计通知**（依赖 T05）
  - 在 `repository_capabilities.go`、`service_content.go`、`memory_sync.go` 接入新能力；增加 handler 和路由。
  - 核查现有 MySQL 增量写入已覆盖新增/替换字段，验证重启后的数据和共享文件引用；本方案原则上无需业务表迁移。
  - 审计记录源课程/课节/资料、目标课程/课节、新增或替换动作及操作者。
  - 复用课程发布通知的权限范围；同批次按目标课程合并通知，失败或无变更重试不发通知。
  - 验收：接口通过认证权限检查；记录重启后仍可读取；通知只到有相应课程权限的学生。

  - 验收：三份文件中一份失败，界面准确显示两份成功，且能只同步这两份。

- [x] **T08：增加同步目标选择弹窗**（依赖 T02、T07）

  - 多选目标课程，每个课程一行选择目标课节，展示完整路径和状态；允许取消某个目标。
  - 切换源资料/目标课程时清空过期推荐和预检查状态。
  - 沿用现有管理端组件和样式，不改课程列表布局。
  - 验收：无成功资料不显示可执行入口；无目标或有未选课节时不能进入确认。

- [x] **T09：接入预检查和覆盖确认**（依赖 T03、T08）
  - 请求预检查，按课程展示新增/替换明细，突出将被替换的原文件及发布结果。
  - 确认按钮文案包含目标课程数量；提交期间禁用重复提交。
  - 权限、目录或资料变化时展示具体可修正原因，刷新预检查后重新确认。

- [x] **T10：结果展示、失败重试及缓存刷新**（依赖 T06、T09）

  - 同步失败时明确“源课程已上传，目标同步未完成”，保留资料和目标选择。
  - 网络结果不确定时按重复提交保护机制重试；不重新上传文件。
  - 验收：关闭同步弹窗不影响源上传；重试不会产生重复资料；刷新后统计与列表一致。
