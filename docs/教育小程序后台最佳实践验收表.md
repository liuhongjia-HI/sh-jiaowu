# 教育小程序后台最佳实践验收表

> 基于会议最佳实践方案、当前代码和本地验证结果整理。用于后续评审时逐项核对“业务闭环是否成立”，不是替代测试报告。

## 验收结论

当前代码已覆盖 P0 业务闭环和大部分 P1/P2 能力：学生身份绑定、学习套餐授权、学习资料管理、题库组卷、练习提交明细、三栏批改、成绩与老师建议、排课日历与冲突检测、站内通知和公众号模板消息记录/补发。

仍依赖外部环境确认的事项：

- 小程序业务域名备案和合法域名配置。
- 微信公众号关联、模板申请审核和真实发送凭证。
- 真机/微信开发者工具里的文件预览与模板消息到达体验。

## 关键验证命令

当前环境中完整 `go test` 偶发挂起，已采用稳定的编译验证和前端构建验证：

```bash
cd learning-api
GOCACHE=/private/tmp/starline-go-cache go test -c ./internal/infrastructure/store
rm -f store.test

cd ../web
npm run build

cd ..
node --check miniprogram/pages/home/index.js
node --check miniprogram/pages/login/index.js
node --check miniprogram/pages/scores/index.js
git diff --check
```

## 评审建议

1. 先演示学生绑定、开通套餐、查看学习资料、完成练习、老师批改、学生查看成绩和通知的 P0 闭环。
2. 再演示排课日历、拖拽确认、冲突阻止和课程通知。
3. 最后演示系统就绪面板，明确外部配置项由运营/部署人员完成，不把真实公众号到达率作为本地代码验收项。
