# 服务号模板消息推送方案（评审定稿）

日期：2026-10-08。依据：本次用户明确的目标、约束和验收条件，以及项目代码和本次线上只读检查。本文替代聊天中前一版推送方案，后续实施按本文推进。

## 一、目标与范围

目标：已登录星际教育小程序、已关注当前服务号的用户，能够收到与其业务和权限对应的服务号模板消息。

已知条件：小程序与服务号已绑定同一开放平台；复用管理后台已配置的唯一服务号，不重新绑定、不新增服务号。首轮测试账号为 `18518673993`，仅发送给该账号，不以年级或全体用户代替测试范围。

核心验收：该账号的手机微信实际收到服务号模板消息，内容和接收人正确。微信接口成功、消息编号、发送回执分别记录，均不能单独代替手机收件确认。点击打开对应内容属于后续业务验收，不阻塞首轮收件验收；已读率不在本轮范围。

本轮先完成定向真实收件及一个真实业务触发闭环。教师教案、其余业务及规模推广分阶段实施。复用已有配置、任务、发送器和回执，不另建一套消息系统。

## 二、评审结论与调整

| 原方案问题 | 优化后的决定 | 原因 |
| --- | --- | --- |
| 把全部业务接入与首次收件混在一起 | 首轮锁定一个测试账号、一条消息、一个业务触发 | 最快定位身份、模板、微信发送的具体阻塞点 |
| 现有手动消息按年级预览和发送 | 增加指定接收人范围，服务端以账号身份限定；测试模式缺少明确目标时拒绝发送 | 同年级可能有其他家长，不能把群体预览当作单人联调 |
| 模板只按字段集合判断匹配 | 同时确认模板业务含义、字段含义、类型及实际内容 | 字段相同不表示课程预约模板适合课前提醒或资料通知 |
| 接收人预览直接比较原始年级 | 使用项目统一的当前年级推导方式，并与实际发送范围共用判断 | 线上原始年级为空，学生列表仍能推导当前年级；此前预览错误返回零人 |
| 以关注者同步的匹配数量代表可发送人数 | 对具体接收人检查有效关注、UnionID、正常账号、有效家长学生关系及业务权限 | 全局身份匹配不等于当前业务可触达 |
| 对不确定结果仅写“不盲目重发” | 修改或约束 worker 的不确定结果重排逻辑，单独验证去重机制 | 现有代码会在十分钟内将部分“结果待确认”重新排队，与此前方案不一致 |
| 教师网页跳转和小程序收件一起验收 | 教师侧后置；家长侧先完成手机收件 | 用户本轮的核心目标是小程序用户收到服务号消息 |

评审结论：采用“先定向验证发送能力，再用真实业务验证触发，最后逐项扩展”的方案。不能将配置就绪、模拟测试或回调地址验证当作推送验收完成。

- 已同步六个公众号模板、两位关注者；同步结果显示两位身份已匹配。
- 测试账号正常，具有 UnionID、有效公众号关注记录，并有一条有效家长学生关系。
- 排课确认、调课、课前提醒和作业提交四项绑定当前为已开启、配置就绪。现有试运行学生范围为空；后续实施的第一步需将联调业务范围收紧到测试账号所关联学生，并记录原配置，验收前不扩大范围。
- 目前尚无本轮真实发送任务与手机收件证据。全局统计与接口就绪不能计为通过。

- 发送器已区分临时错误、配置错误及结果不确定；worker 和手动消息均有回执处理。仍需核对两条发送路径在去重、重试、持久化和状态展示上的一致性。

## 四、身份与触达规则

链路：小程序登录身份 → UnionID → 当前服务号关注者的 OpenID → 正常接收账号 → 有效学生关系及业务权限 → 发送任务。

1. 手机号仅用于管理端定位测试账号，不用手机号推导 OpenID，不允许客户端提交任意 OpenID 作为接收人。
2. 只能使用当前服务号的 OpenID，不能使用小程序 OpenID，也不能用别人的关注身份补齐。
3. 绑定开放平台不会自动补齐历史 UnionID。缺失时优先提示该用户重新登录小程序，并同步或刷新公众号关注身份；不修改账号归属。
4. 没关注、取消关注、UnionID 缺失或匹配不唯一、账号停用、学生关系失效，分别返回可理解的原因。关注是必要条件，不是充分条件。
5. 预览、生成任务、真正发送时使用一致的触达判断；发送前重新校验。指定接收人列表为空或账号解析有歧义时，测试发送必须拒绝，不回退到所有用户。
6. 家长多子女按具体业务中的学生和权限处理；同一次业务针对同一个公众号接收身份去重。

## 五、模板与业务接入

| 业务 | 接收人和触发 | 当前模板情况 | 实施安排 |
| --- | --- | --- | --- |
| 排课确认 | 相关学生的有效家长；正式确认后 | 已有“排课时间已确认通知” | 优先作为真实业务闭环候选，先核对测试账号是否有适用业务 |
| 调课成功 | 相关学生的有效家长；正式生效后 | 已有“调课成功通知” | 首轮通过后验证调前、调后及重复提交 |
| 课前提醒 | 相关学生的有效家长；课前提醒窗口 | 当前绑定“课程预约结果通知” | 必须核对语义；不合适时改为课前提醒模板，不仅凭字段一致判定 |
| 作业提交成功 | 提交学生的有效家长；提交保存成功后 | 已有“作业提交成功通知” | 优先作为真实业务闭环候选，不伪造提交 |
| 讲义批量发布 | 当前有资料资格的学生家长；批次完成后 | 缺适用模板 | 保留已有批次汇总，补模板及字段映射后单独验收 |
| 作业发布 | 有作业访问权限的学生家长；正式发布后 | 缺适用模板 | 已有站内事件，补外部字段映射、任务校验及发送接入 |
| 批改完成 | 对应学生的有效家长；最终批改完成后 | 缺适用模板 | 待复核不发送；补外部发送字段及任务有效性检查 |
| 课程取消 | 被取消课程的相关家长；正式取消后 | 缺适用模板 | 补模板、任务值及取消后打开内容的说明 |
| 批改异常 | 对应学生的有效家长；老师明确标记后 | 已有“作业批改异常提醒” | 触发流程尚未接入，保持关闭；与正常最终批改区分 |
| 教师教案上传 | 当前有教案权限的相关教师；批次完成后 | 缺适用模板 | 教师侧后置；使用教师网页及教师身份，不复用学生身份 |

模板字段来源建议：讲义使用课程名称、资料名称、数量、发布时间；作业使用课程名称、作业名称、学生姓名、发布时间或截止时间；批改使用作业名称、学生姓名、完成时间；取消使用课程名称、学生姓名、原上课时间及适用原因；教案使用教案名称、数量、上传时间、年级学科。具体字段键和允许值必须以服务号实际添加的模板为准，不编造模板编号或通过凑字段替代业务语义。

独立联调消息必须明确标注“推送联调测试”，不伪造排课确认、作业提交或批改状态。使用已有模板前确认业务语义允许承载该内容；不适用则先准备适用模板。缺模板只阻塞对应业务，不要求首轮先完成全部模板。

## 六、任务状态与重试

- 生成任务：保存业务事件、接收人、模板版本、字段值、业务去重编号和状态；沿用已有持久化结构，按需扩展，不直接修改生产数据库构造假任务。
- 发送：执行前复核关注、身份、权限和模板映射；业务失败或配置不完整不标记成功。
- 微信已受理：记录消息编号和受理时间，不能显示为用户已收到或已读。
- 回执送达：验签解密后按消息编号与接收 OpenID 匹配，处理重复和先到回执，记录送达时间。
- 暂时失败：按现有有限次数和退避机制重试；配置错误等待修复，不循环发送。
- 结果待确认：首轮默认不自动重发。先查已存消息编号、回执和日志；若日后保留自动重发，须先证明相同幂等编号和平台去重适用于该接口及有效时段，不把应用层去重当作平台收件不重复的保证。
- 手机确认：作为验收记录单独保存，不伪造微信回执、不改为“已读”。

## 七、执行顺序与每步完成条件

| 步骤 | 工作 | 完成条件 |
| --- | --- | --- |
| A：基线与范围 | 记录当前配置及已有任务；解析测试账号，核对唯一关注身份及学生关系；收紧联调业务接收范围 | 页面或接口明确显示测试账号、关联学生、关注与匹配状态，以及不可触达原因；不修改真实业务数据 |
| B：必要修复 | 修复预览年级和字段标签；增加指定接收人发送范围；统一预览与实际目标；处理不确定结果重排 | 隔离测试证明只选一个账号时不会生成其他人的任务；错误账号、重复请求、失败恢复均可检查 |
| C：定向真实发送 | 预览实际模板和内容，生成一条明确的联调记录，仅发送给测试账号 | 恰好一位目标接收人；产生真实发送记录；记录微信返回和回执结果；不可确定时不反复试发 |
| D：手机收件验收 | 用户在该账号手机微信确认服务号消息、内容和时间 | 手机确实收到本轮消息；未收到则按身份、请求、回执、消息列表逐层定位，不能宣告通过 |
| E：真实业务闭环 | 从已有排课确认或作业提交中选择实际适用业务；由正确操作触发通知 | 实际业务成功后正确用户收到一次；重复提交不重复通知；不改动真实课消或制造假业务 |
| F：逐项扩展 | 补其余模板和接入，逐业务开启；教师侧独立验收 | 每项有触发、范围、字段、失败处理和手机验收证据；再扩大接收范围 |

实施时优先使用当前发送器和任务记录。新增定向联调路径与业务自动通知共用身份校验、字段验证和回执处理；不以直接调用微信接口绕过管理后台、任务持久化及接收人检查来凑验收。

## 八、验证及交付

针对性验证：当前年级预览、指定账号限制、未关注及取消关注、身份缺失或歧义、关系失效、业务去重、模板字段类型、发送失败与结果不确定、回执乱序和重复、服务重启后的任务状态。测试数据与真实业务隔离。

页面验证：管理员能够查看测试目标、发送内容、当前状态及失败原因；“已受理”和“回执已送达”清楚区分。后台实际渲染验证不能由 TypeScript 或构建检查代替。

交付记录至少包含：测试账号、实际模板及内容、任务或发送记录编号、发送时间、微信返回状态及消息编号、回执状态及时间、手机收件确认、重复通知情况。各项明确标注“通过／失败／未验证”；后续业务另行记录。

当前结论：配置和身份基础已具备，定向发送范围及必要缺陷仍需实施，真实手机收件尚未验收。本次只保存评审方案，没有执行代码修改、生产发布或新消息发送。

### E07 实施决策补充

批改异常使用独立教师操作，不扩展“待复核”的含义。老师填写该作业的实际班级，原因只能选择从微信审核结果配置的值；不得用课程名或套餐名冒充班级。操作不改评分、不制造提交结果；用稳定请求编号及当前异常事件防止重复和过期请求恢复旧异常。继续批改保存成功后解除异常，发送前重新校验当前异常、作业、审核原因和接收权限。审核原因仍缺失时保持不可启用，隔离测试值不能写入线上。


### E08 实施决策补充

教师通知 URL 同时保留单份 plan 与批次 notice。登录后返回原批次；批次接口只对正常收件老师开放，以当前权限筛选所有资料。手机宽度的通知直达页优先显示批次资料，另可返回全部教案。历史单份 URL 继续可打开，但首屏和真实文件验证仍须由实际教师手机完成；本地浏览器视口不能替代真机验收。
