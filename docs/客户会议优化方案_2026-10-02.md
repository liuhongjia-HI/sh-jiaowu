# Starline 客户会议优化方案

会议日期：2026 年 10 月 2 日。整理日期：2026 年 10 月 3 日。

本方案合并会议反馈、客户提出的处理方式及多轮讨论中的评审意见，共整理 24 项需求，覆盖课程讲义与提醒、教师配置、教案管理、排课四类流程。目标是减少重复操作，同时保留必要的权限与业务约束，作为后续实现和验收的依据。

## 整理后的推荐方案

客户反映的操作成本需要解决，具体做法按现有业务约束调整后落地。优先采用以下方案：

1. **浏览与入口先修复**：返回保留筛选、搜索、分页和位置；讲义页显示当前课程名称；教师姓名完整；明确可上课时间入口，移除工作周，保留可见新增按钮。
2. **教师范围填写一次**：以多组“年级＋学科”配置授课范围，查阅默认跟随；额外查阅、操作能力和历史精确限制分别保留。停用教师保留历史，并处理未来课程交接。
3. **资料维护复用现有章节**：目录与讲义分别同步、分别预览；教案关联统一章节但保持教师内部资料权限。先完善多文件上传、逐份预览和失败重试，再评估文件夹及 ZIP 导入。
4. **排课围绕老师组织**：老师优先带出课程，学生姓名搜索多选，同名补充识别信息；就地修改教师范围时保留草稿；自定义日期逐日设置时间并整批检查。计划招收人数可选，班型容量继续限制。
5. **视图按任务分工**：月和列表采用紧凑课卡，日周保留时间轴；高密度日期提供完整课程列表。取消、恢复和调课继续遵循冲突检查及单次、系列边界。
6. **下载与提醒形成闭环**：可访问的已发布讲义异步打包，创建与领取均检查权限；一次操作汇总相关资料提醒，以隔离师生身份验证触发及打开结果。

本轮已定稿：**人数不足仍可排课，线下老师决定成班；额外查阅只读，下载独立授权；已上课只处理排课状态，不涉及课消**。验收使用隔离教师、学生身份，验证后取消测试课次，不等待真实客户设备或外部收件。详细规则见第九节。

状态：方案已定稿，约定范围已完成本地实施与隔离身份验证，未提交、推送或发布；逐项证据与限制见实施记录。文中的“推荐方案”属于评审建议；业务边界已按用户最新答复确定。会议中的配置操作和开发方所述已有修改，均不代表功能已上线或验收通过。

当前实施进度与验证证据见[实施记录](客户会议优化实施记录_2026-10-03.md)。

## 方案评审结论

客户反馈的主要问题成立，但提出的具体办法并非全部适合直接照做。推荐按以下决策推进：

| 决策 | 涉及建议 | 推荐处理及理由 |
| --- | --- | --- |
| 直接采纳 | 返回保留筛选、老师优先排课、学生姓名搜索多选、入口改名、去掉工作周、修复姓名遮挡 | 直接降低重复操作，业务含义明确；补充浏览位置恢复、同名识别和现有上下文保留。 |
| 调整后采纳 | 简化教师范围、合并查阅与教学配置 | 界面默认按年级和学科填写一次，但授权仍区分授课、额外查阅和操作能力，保留历史精确限制，防止扩大权限。 |
| 调整后采纳 | 目录页同步、教案沿用章节、本科目全部下载 | 复用已有目录和材料能力；增加同步预览、章节引用保护、权限范围内的异步打包与领取校验。 |
| 调整后采纳 | 不规则日期排课、取消预计人数必填、紧凑彩色课卡 | 多日期逐日校验后整批提交；预计人数改为可选并保留容量；月和列表用课卡，日周保留时间轴。 |
| 分步实施 | 文件夹或 ZIP 上传、服务号和上传提醒 | 先把多文件上传、失败重试及逐份预览做好，再判断是否需要 ZIP；提醒分别验证配置、触发、收件与打开结果。 |
| 已定稿 | 人数、额外查阅、已上课 | 不设置最低成班人数；查阅不扩大操作权；已上课不接入课消。 |

实施顺序为：先修复浏览和配置一致性，再简化教师与排课流程，随后完善同步、教案和批量资料处理，最后完成复杂排课及隔离师生权限验收。每项需求的具体范围、约束和验收标准见下文。

### 建议是否最合适的评审依据

本方案的“推荐”指在现有系统和会议描述的使用场景下，综合操作效率、业务正确性、历史兼容及实现成本后的优先选择；没有真实使用数据的部分仍需通过代表性用户验收确认，不能认定为所有场景下的最优解。

| 客户建议 | 综合评审后的选择 | 选择依据及适用条件 |
| --- | --- | --- |
| 教学和查阅范围合在一起 | 一次填写授课范围，查阅默认跟随，额外查阅和操作能力独立 | 减少重复配置，同时支持跨范围备课；直接合并授权会让查阅权限扩大为排课或修改权限。历史精确限制保留。 |
| 从目录页同步到其他班型 | 目录页提供入口，目录与讲义分别预览和执行 | 操作上下文合理，但结构与文件的覆盖风险不同；同步前说明对应关系及引用影响，避免误覆盖目标内容。 |
| 文件夹或 ZIP 批量上传 | 先交付多文件上传、逐份章节关联、预览和失败重试 | 直接解决重复上传问题，复用现有文件管理；只有基础流程仍不足以处理实际资料量时，再增加导入和安全解压成本。 |
| 本科目全部下载 | 当前权限范围内异步打包，创建和领取时再次校验 | 大量资料不能依赖同步请求；“全部”必须排除草稿、无权资料和内部教案，且不能用漏文件的包表示成功。 |
| 排课只显示学生姓名，预计人数线下控制 | 姓名为主，同名补充识别；计划人数可选，容量继续约束 | 简化表单成立，但同名误选和超容量仍需系统防止；线下老师决定成班，不设置最低人数阈值。 |
| 所有日历都改成紧凑彩色课卡 | 月和列表采用课卡，日周保留时间轴 | 月视图需要提高浏览密度，日周需要比较空闲、重叠及拖动调课；颜色分类保持统一，高密度日期提供完整列表。 |
| 上传后立即发提醒 | 按一次操作汇总成功且符合发布条件的资料，发送前复核权限 | 避免逐文件重复提醒和失败文件提前通知；站内未读与外部送达分开验收，配置成功不能证明用户收到。 |

若真实使用发现上述方案仍有明显操作成本，先记录具体场景和失败原因，再调整对应流程；不以新增更多入口、标签或批量能力代替问题验证。

## 三 教师配置与权限方案

### 默认配置流程

新增或编辑教师时，按姓名、手机号、授课范围、操作能力、账号状态组织信息。授课范围支持多组“年级＋学科”，例如四年级地理和五年级中文。展示时以这两项为主，不默认展开学期、季度、班型等长串标签。

资料查阅范围默认跟随授课范围；有跨年级备课需要时，展开“额外资料查阅范围”补充配置。上传学习资料、上传练习、维护课程、批改和下载等能力保留独立开关，避免能看资料即获得修改权限。

### 权限边界

- 额外查阅范围不会自动成为授课范围，也不会自动成为排课课程候选。
- 精确班型或阶段限制作为高级设置保留，并在列表中提示存在特殊限制。
- 变更权限须有服务端校验，不能只调整表单或隐藏入口。
- 旧账号迁移前记录现有查阅范围、管理范围及能力；默认保留有效访问和已有操作限制，不因新界面自动扩大权限。
- 教学配置停用后，禁止新增无效选择；历史关联仍可识别，提示管理员调整。
- 停用教师阻止新登录和新排课；已有会话、未来课程交接作为验收项，历史归属不删除。

现有实现中，`teacherLibrary.scopes` 与 `learningSpaceIds` 分别参与资料查阅和教学管理，不能直接删掉任一字段完成“合并”。推荐先统一界面配置，再落实范围解析与兼容规则。

## 四 课程目录与跨班型同步方案

课程列表通过返回操作恢复原筛选和浏览位置。选中课程后的讲义页大标题采用当前课程名称；课节条目以章节、课节名称为主，文件类型、版本和操作作为辅助信息。未选课程时保留“课程讲义”名称，顶部分类名称不随课程切换。

在课程目录维护界面增加“同步到其他班型”，明确操作对象：目录结构、已发布讲义，或两者。同步与保存分开，避免维护一个班型时自动改动其他班型。

推荐流程为：保存源课程改动 → 选择同步内容 → 选择同范围目标班型 → 核对目标章节及新增、覆盖预览 → 执行 → 查看逐目标结果。

复用现有讲义同步的范围检查和覆盖预览。目录同步增加对应的结构检查；不能仅凭章节同名确定对应关系。目录变更如会影响目标已有材料，应在预览中说明，避免清空或孤立材料。重复提交不得产生重复条目，失败目标可以单独重试。

## 五 教案章节与批量上传方案

教案沿用相同教学范围的章节体系，文件内容与学生讲义分开。实施前明确统一目录的归属范围，至少核对年级、学科、学期和阶段；不能让同一学科不同阶段的教案都绑定到一套目录。

优先复用已有课程目录能力，不为本次需求引入全新的目录平台。上传教案时选择教学范围和章节，单一可用范围自动带入。已有未关联章节的教案保留，归入“未归类”，由管理员后续关联，不删除或强行推断章节。

章节改名与排序更新展示；章节删除或目录切换时，应显示引用影响并提供重新关联方式。历史教案仍能找到。内部教案不得进入学生端列表、讲义同步或学生下载包，详情、预览和下载接口均保持权限限制。

第一阶段增强现有多文件上传：拖入或选择多份文件、自动生成标题、统一或逐文件指定章节、显示上传及预览状态。成功文件不重复提交，失败文件单独重试。

文件夹导入和 ZIP 导入列为后续增强项。导入前展示文件清单和章节归属，导入后拆成独立教案，沿用现有预览流程。ZIP 实现需限制文件类型、文件数及解压体积，检查路径，逐文件反馈结果；不以新增压缩包下载按钮作为完成标准。

## 六 批量下载与资料提醒方案

### 批量下载

下载入口清楚显示本科目下的可访问课程范围、材料数量和预计大小；可按阶段或章节缩小范围。大包异步生成，显示准备中、可下载、失败和已过期等状态，支持重试或重新生成。

包内按课程和章节组织文件，处理同名文件，并注明生成时间。权限在创建下载任务和领取文件时检查，排除草稿、无权材料及内部教案。打包失败须反馈，不能将漏文件的结果显示为完整成功。

电脑端使用受控的领取入口，不暴露服务器目录。移动端的实际下载、打开与电脑领取流程需分别验证，再决定是否提供设备引导。

### 资料提醒

教师端提供新增资料入口、未读标记及返回查看能力。外部提醒按接收人相关范围发送：家长接收已发布且可访问的学生材料，教师接收对应范围的资料或教案。批量上传按一次业务操作合并，失败或仅上传未发布的材料不提前通知。

服务号配置完成、模板映射正确、业务触发产生通知、用户实际收到并打开材料，分别记录验证结果。配置失败、发送失败可追踪和重试，重复重试不重复推送。会议中讨论过的配置不作为当前状态证明；凭据继续由受保护配置管理。

## 七 排课表单方案

默认顺序为老师 → 课程 → 班型及学生 → 上课日期与时间 → 重复方式。其他低频设置按需展开，不堆成同权重字段。

- 教师日历内创建自动带入老师；课程入口创建自动带入课程，避免丢失当前上下文。
- 课程候选来自老师授课范围，只展示有效课程；候选很多时使用年级、学科筛选和搜索，不默认增加更多标签层级。
- 更换老师、课程后校验已选课程和学生，明确提示不匹配项，不静默替换或清空。
- 学生支持姓名搜索和多选；普通候选姓名为主，同名时补充年级等识别信息。课程适用资格继续校验，不把跨年级一概判为无效。
- 班型容量继续限制人数。预计人数不作为默认必填；若业务需要预排占位，改为可选“计划招收人数”，不设置最低成班阈值。
- 有权限管理员可以在当前排课流程中快捷调整老师授课范围，保存后刷新候选，保留已填日期、时间和学生草稿。
- 自定义日期支持多日期与逐日时间，保存前列出课次、冲突和不可提交项。推荐先校验整批，明确失败原因，不默认接受无提示的部分成功。
- 沿用已有冲突检查、审核、课次和系列规则；不以表单简化为由取消后端限制。

## 八 排课视图与操作方案

日、周视图保留时间轴，用于比较老师空闲、发现重叠和拖动调课。月视图和列表采用紧凑课卡，服务于快速查看当天所有课程。

课卡信息顺序为时间、学科与班型、老师、学生。所在视图已经明确的老师等上下文可以减少重复展示，但完整详情仍可打开。课程按时间排列，颜色使用统一的一种分类规则，课程状态另用图标表达。

课程较多时允许日期区域展开或进入当天完整列表，提供明确的课程数量提示。不能靠无限缩小字号、无法发现的悬浮信息或默认折叠隐藏课程满足高密度展示。

已上课、取消和调课可提供快捷入口，操作应有结果反馈。取消保留记录；未结束的取消课次可在预检后单节恢复，重新检查老师状态、授课范围、学生资格和时间冲突，保存时再次校验。恢复保留原课次编号和系列关系，不连带恢复其他取消课次。调课沿用冲突预检和单次、后续、系列边界。“已上课”仅记录排课状态，不接入出勤、课消或计费。

保留顶部新增按钮，双击空白处作为桌面增强入口。检查现有双击逻辑和未提交的日历改动，确认缺口后再修改。去掉工作周，修复教师姓名遮挡，明确教师可上课时间入口。

## 九 已确定的业务规则与验收边界

| 规则 | 最终方案 | 边界 |
| --- | --- | --- |
| 人数不足 | 仍可排课，空名单可预留；计划人数可选，留空按已选人数记录 | 线下老师决定成班；系统保留最大容量、时间冲突、学生资格及审核校验 |
| 额外查阅 | 仅查看、预览；下载独立授权 | 不因此增加上传、修改、删除、课程管理、批改或排课权；操作仍受授课范围与能力开关控制 |
| 已上课 | 仅为排课状态 | 不处理考勤、请假、扣课时或费用 |
| 验收 | 临时服务中以教师、学生身份验证，验证后取消测试课次并释放存储 | 不要求真实客户设备、外部收件；不执行生产写入或外部发送 |

额外查阅参考常见资料系统的查看/编辑分权：[Google Drive 官方权限说明](https://support.google.com/drive/answer/2494822?hl=en)中 Viewer 不能编辑，下载由所有者控制；[NIST 最小权限原则](https://csrc.nist.gov/glossary/term/least_privilege)要求只授予完成职责需要的权限。结合跨年级备课用途，本项目选择只读加独立下载授权，不声称所有教育机构采用同一规则。

## 十 分阶段实施

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |

| 第三阶段 | M03、P03、P01 的多文件体验、P02、M04 | 同步预览可靠，教案章节关联稳定，批量上传和下载失败可恢复 |

## 十一 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 从讲义返回并切换班型 | 筛选、搜索和浏览位置保留，无需重新选择年级、学科 |
| 教师有两组授课范围及一组额外查阅 | 分别正确展示和访问；额外查阅不自动允许教学操作或排课 |
| 旧权限账号迁移 | 有效查阅不丢失，操作权限不扩大，特殊限制可识别 |
| 教师停用 | 登录与新排课受限制，历史课次和材料归属完整，已有会话和未来交接已核对 |
| 教案章节维护 | 改名、排序正确更新；删除引用不丢文件；未归类旧教案可继续访问 |
| 学生直接访问教案 | 列表、详情、预览、下载均拒绝；学生下载包不包含教案 |
| 多文件上传部分失败 | 已成功文件不重复，失败文件原因明确，可单独重试并最终预览 |
| 跨班型同步 | 范围及章节对应有效，覆盖事先可见；重复执行不重复新增；失败目标可恢复 |
| 本科目批量下载 | 内容完整且符合权限，目录清楚；过期、失败、无权状态有可执行处理方式 |
| 老师优先排课 | 只推荐授课范围内课程；改变老师或课程后重新校验已有选择 |
| 同名学生与班型容量 | 姓名可识别，多选对应正确账号；切换到较小班型时保留已选学生并提示调整，不静默删选；超容量由前后端阻止，计划人数留空按已选人数记录，少于容量仍可排课 |
| 不规则日期排课 | 日期和逐日时间正确，冲突明确，不产生无提示的部分提交 |
| 月视图高密度展示 | 当天全部课程有可发现的查看路径，信息可读，长姓名不遮挡操作 |
| 日周调课及系列 | 冲突检查、审核、历史课次和系列修改边界正确，不因视图调整改变业务行为 |
| 已上课 | 仅结束、通过审核且未取消课次可由教务或授课老师标记；只改排课状态，重复提交不重复处理，不扣课时 |
| 资料提醒 | 仅发送给有权限且相关的用户；批量不逐文件轰炸；在隔离师生身份下验证触发、可见范围与打开；不要求真实外部收件 |

实施验证以受影响的前后端检查和代表性页面为主。权限、上传、同步和排课规则变化需要针对性接口与持久化验证；纯名称和显示调整不默认触发全量测试。截图、构建成功、配置成功和真实业务验收分别记录。
