# Unit 同步规则与修复

## 原因

首次同步按完整名称路径匹配。源 Unit 有名称、目标同编号 Unit 无名称时会新建分支，目标旧讲义仍绑定原节点。旧分支的删除保护正确阻止了直接删除。

## 本次行为

- 默认同步选定 Unit 及下级目录、已发布讲义，可取消勾选改为仅同步目录；不复制源教案和课后练习。
- 同编号或多个对应候选须明确选择目标节点，再次预览后确认。编号仅作为候选线索。首次未建立对应关系时，也可以明确选择新增为不同章节。
- 已重复的分支可勾选合并。保留所选目标节点 ID，迁移被合并分支上的讲义、练习、教案关联；下级有多重对应时拒绝合并，已有资料的末级节点不能直接变成非末级节点。
- 讲义来源对应关系保存在目标课程现有的 `directory_sync_json` 中，使用独立的 `material:` 键。无需增加数据库字段。已追踪的同步讲义保持材料 ID，更新内容和文件引用，保留阅读次数、创建时间及排序；目标自有和没有来源标记的历史资料保留。
- 源讲义被删除、撤回或停用不回收目标副本。草稿不复制；选中范围内已发布讲义缺少标签或文件时阻止同步，避免静默漏文件。
- 预览包含目录、合并对应关系、讲义新增和更新。保存时复核当前目录、资料、文件和关联；变化后必须重新预览。一次目标操作在已有持久化事务中保存，重复请求不重复新增。
- 不额外开启服务号自动通知或发送外部消息。

## 验证边界

后端 store 用例覆盖名称差异、明确选择、历史重复合并、讲义/练习/教案关联迁移、讲义版本更新、旧预览拒绝、源删除保留目标、仅目录模式、缺失文件、非法合并节点和重复提交。

真实本地 HTTP 用例覆盖有效 PDF 上传、冲突阻断、保留目标节点 ID、目录与讲义一起同步、保留目标自有讲义、重复请求、学生权限拒绝，以及原文件下载字节一致。

页面验证使用实际 React 页面与模拟 HTTP 响应；不替代真实数据库或线上历史数据验收。本次不执行生产数据清理或发布。生产历史重复分支需在新预览中核对并确认后合并。
