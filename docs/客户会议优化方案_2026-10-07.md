# Starline 会议需求实施方案

日期：2026 年 10 月 7 日。

本方案对应[会议需求清单](客户会议需求清单_2026-10-07.md)的 13 项需求。优先简化目录同步和教案维护，再调整教师列表、补齐移动端下载及公众号通知流程；组合课程单独安排。已核对本地代码，并按用户要求实施了可确定部分，详见[实施记录](客户会议优化实施记录_2026-10-07.md)。现有代码能力不代表生产和真机验收已通过。

## 方案取舍

| 工作内容 | 处理方案 | 对应需求 |
| --- | --- | --- |
| 目录同步 | 将目标班型选择放进目录编辑流程；复用现有预览和同步，增加单 Unit 范围 | 1、2 |
| 教案浏览 | 按课程归组，与课程页使用一致的筛选和课程标识；教案文件独立维护 | 3、4 |
| 教案上传 | 课程必选，章节可选；一次选多份文件，允许后续补充章节 | 5 |
| 筛选与文案 | 年级、学科、学习阶段用标签；学年口径确定后接入；精简重复中文说明 | 6、7 |
| 教师列表 | 按最终标注重排列，拆分常用操作与停用删除，修复固定列遮挡 | 8、9 |
| 移动端下载 | 复用异步打包和电脑领取链接；按实际使用角色补入口及登录流程 | 10、11 |
| 公众号通知 | 基于已绑定开放平台的现状，核对身份、模板及触发，完成收件和打开验收 | 12 |
| 组合课程 | 后续增加展示分组，引用现有课程，另行确定结构及业务影响 | 13 |

班型选项来自系统实际配置，S、S+、H、H+ 仅作会议举例。继续沿用现有教师授课、额外查阅和下载授权规则。

## 一 目录同步

### 用户操作

在目录编辑抽屉顶部提供“同步整套目录”，各 Unit 区提供“同步此 Unit”。点击后就地显示同年级、学科、学期和阶段的目标班型勾选项，不跳到其他课程页面。

新增 Unit 后勾选目标班型，点击“保存并预览同步”：先校验并保存源目录，再在当前流程展示目标变化，确认后执行。未选目标时，普通“保存”只保存当前课程。确认同步前显示源课程、同步范围、目标班型和新增、更新数量；只有发生差异或错误的目标展开详细信息。

例如：S 班新增 Unit 3，勾选 S+。保存后只预览 Unit 3 及其下级节点，S+ 原有 Unit 1、2 和资料保留。整套同步使用相同流程，但范围为全部目录。

### 推荐规则

- **默认合并，不删除目标独有内容。** 新增缺少节点，更新已建立对应关系的节点；讲义、练习和教案不随目录自动复制。
- 单 Unit 同步包含该 Unit 下的 Chapter、Lesson，不影响其他 Unit。服务端计算子树，不信任前端提交的节点清单。
- 复用已有节点对应关系。没有对应关系时按完整层级路径识别，不能仅凭序号或叶子名称认定相同。同编号不同名称、映射冲突等歧义明确提示，当前目标暂不写入，其他目标显示各自结果。
- 同一课程系列已共用目录时显示“已共用目录”，无需复制；属于另一套共享目录的目标沿用现有限制，提示到课程系列维护。
- 保存源目录成功、同步失败时，分别显示结果；保留目标选择，仅重试失败目标。不能把整个操作显示为全部失败，也不能丢失已保存的 Unit。
- 执行前复核源、目标和所选范围的版本。预览后被其他人修改，则重新预览；重复执行不增加重复节点。

本轮推荐不提供“整套覆盖并删除目标内容”。如果确有覆盖需求，应单独确定对已有资料引用的处理规则。

### 实现范围

复用 `CourseDirectorySync` 及 `/api/courses/directory-sync-preview`、`/api/courses/directory-sync`。现有接口只同步整套目录，建议增加可选 `unitIds`：未传表示整套，传入表示这些 Unit 及后代；预览与执行使用同一范围，版本校验包含范围。

调整目录抽屉和保存回调，让服务端保存后的节点 ID 进入后续同步，避免使用未保存的临时 ID。既有保存逻辑目前会提示“请先保存目录修改，再进行同步”，本轮把两步串在同一操作流程中。

## 二 教案浏览与上传

### 页面组织

页面保留一个标题“教案”，浅蓝色用于页头或分区标识，内容区继续使用可读的白底。筛选区与课程页保持一致；下方以课程为入口，展示课程编码、学期阶段、适用班型、教案数量，进入后显示该课程的教案列表。

同系列多个班型共享目录时，教案按系列归组并显示适用班型，避免同一份文件重复出现；最终可见范围仍由后端按当前账号计算。沿用现有预览、下载、未读和章节补充能力。

历史上未关联课程的教案保留在“未关联课程”入口，可按年级学科查找并补充关联。已关联课程但没有章节的资料显示“课程通用”，不会因为章节筛选而消失。

### 上传流程

从课程内点击“上传教案”，自动带入当前课程；从全局上传时，先选择有权上传的课程，再选择文件。文件支持一次多选，标题默认取文件名。

“统一章节”标明可选，默认留空，不因课程只有一个章节就自动赋值。需要时可为整批设置章节，也可为单份设置不同章节。单份支持“跟随统一章节”“不关联章节”“指定章节”三个明确状态，避免清空单份章节后又被统一设置填回。

上传逐文件显示成功或失败，成功文件不重复上传，失败文件可单独重试。通知继续沿用已有批次汇总；只有成功文件进入汇总，重试不产生重复提醒。

### 前后端配套

当前前端在存在课程目录时强制每份选章节，而且只在课程与章节同时存在时提交 `courseId`。后端允许二者都为空，但不支持有课程无章节。因此不能只删除前端提示。

调整为：

| 提交情况 | 新上传处理 |
| --- | --- |
| 有 `courseId`，没有 `lessonId` | 校验课程、年级学科及上传权限，保存课程归属与学期阶段；章节留空 |
| 有 `courseId`、`lessonId` | 同时校验章节属于所选课程，沿用章节关联 |
| 没有 `courseId`，有 `lessonId` | 拒绝，章节必须有课程归属 |
| 二者都没有 | 新上传要求选择课程；历史未归类记录继续可读，旧客户端接口兼容规则单独保留 |

更新 `assignPlanChapter`、关联章节接口和目录引用维护：课程通用教案在目录改名、排序后仍属于原课程，不错误要求解析空章节。切换课程时只清除不再适用的章节选择，保留待上传文件和标题。

## 三 筛选与学年

### 可以直接执行的部分

课程页和教案页统一为“学年、年级、学科、学习阶段”的布局。年级、学科及阶段采用可点选的标签；选项多时允许换行，不用无限横向滚动。学习阶段沿用现有学期与阶段的组合，如 S1 Q1，不新增另一套编码。

选择年级后更新合法学科，选择学科后更新课程；班型在结果中展示，不重复作为必选项。搜索和状态筛选保留为辅助操作。继续复用列表状态保存能力，返回恢复筛选、搜索、页码和位置。

列表以实际课程名称或编码为主，阶段用紧凑编码，班型单独标识；详情和编辑表单保留完整名称，避免为精简展示而修改业务值或解析课程名称。

### 学年需要明确业务含义

现有课程、课程系列和教案没有有效的学年版本字段；学习空间的 `academicYear` 是历史兼容字段，不参与业务匹配。学年选项应来自系统校历 `academicCalendar`，不能直接读取历史字段，或按上传日期推断归属。

推荐在需要年度资料差异时，采用**学年版本加通用资料**：

1. 课程和课程系列增加可选学年归属；空值明确表示通用。教案继承所选课程的学年，不单独重复填写。
2. 查看某学年时显示该学年版本及通用资料，分别标识；旧资料先全部保留为通用，之后由管理员选择性归类。
3. 共用目录只在相同学年版本或同一通用系列内维护，跨年复用通过明确的创建版本操作，不让修改本学年目录连带改变历史版本。
4. 目录同步、教案课程候选和批量下载范围同时校验学年，数据库兼容旧记录，补充持久化和重启验证。

如果学年只表示当前校历上下文，则保持资料跨年共用，界面显示当前学年，筛选仍只按年级学科阶段；不制作一个对结果没有作用的学年筛选。

**方案暂按需要学年版本设计，实施前确定以上两种口径。** 这会影响数据结构与迁移，不能作为纯界面改动处理；其他模块可独立推进。

## 四 教师管理表格

推荐完整列顺序：

**常用操作 → 姓名 → 资料查阅范围 → 授课范围 → 可上传内容 → 可批改 → 手机号 → 登录方式 → 账号状态 → 备注 → 账号操作。**

常用操作包括编辑、重置密码（会议中的钥匙图标），放在最左；右侧账号操作只放启用或停用、删除。保持原有确认与历史记录保护，不改变权限配置和账号规则。次要列的插入位置属于本方案的实现建议。

只固定左侧常用操作和姓名，右侧账号操作按普通列滚动，减少两侧固定区挤压正文。为姓名和范围设置适当宽度，范围标签换行；移动端沿用已有卡片模式，不把桌面表格挤成多列小字。卡片中的字段和操作顺序同步调整。

验收至少覆盖 1440、1280 像素宽度及移动端：长姓名、多组范围、横向滚动、停用账号和重置密码操作均可读可用。

## 五 移动端批量下载和电脑领取

### 已有能力

后端已有资料范围核对、异步打包、任务列表、重试和领取权限检查。网页已有“复制电脑领取链接”，链接格式为 `/teacher-library?downloadJob=...`；登录跳转能保留任务参数，并要求创建任务的同一账号领取。

原生 `miniprogram/` 当前是学生和家长流程，页面清单未包含教师资料库或批量下载页。后端现有批量接口限制教师及教务。不能只在学生页加按钮就调用教师接口。

### 推荐使用流程

按教师及教务使用规划：资料入口 → 选择课程或当前科目 → 核对文件数和大小 → 生成下载包 → 查看任务状态 → 复制电脑领取链接 → 微信传到电脑 → 同一账号登录并下载。

入口优先带入当前课程，另提供“本科目全部可下载讲义”；“全部”由服务器按当前授权和已发布资料计算。打包中显示状态并允许离开页面；重新进入可找到任务。失败可重试，过期可重新生成，空资料范围不能创建空包。

### 分步落地

1. 先核对教师手机网页入口及电脑领取路径，沿用现有能力完成代表性闭环。
2. 如需求确指原生小程序，补齐教师身份识别、绑定及角色入口，再增加精简的讲义下载页；只做浏览、打包和复制链接，不扩展成完整教师后台。角色识别必须由后端判定，不能根据前端按钮或身份选择授予权限。
3. 领取链接采用已配置的教师网页域名，链接只携带任务 ID，不携带登录令牌。同账号校验、下载授权撤销和有效期检查继续在服务器执行。登录后恢复任务，不能落到普通首页让用户重新寻找。

**方案暂按教师及教务使用。** 如果家长学生也需要，应另加学生资料范围的批量接口、身份与授权检查，并设计家长在电脑上登录及绑定学生的领取方式；不能沿用教师账号登录或放开教师打包接口。

本轮电脑下载是主要交付路径；手机 ZIP 下载是否提供增强入口，按实际设备验证结果决定。

## 六 微信公众号消息推送

公众号已绑定开放平台是用户确认的当前条件。继续在管理后台“系统设置 → 小程序与公众号”以及通知配置页维护参数，复用现有消息发送和任务记录。

### 联调内容

1. 核对现有公众号配置、模板及字段映射、回调和关注者同步；保留已保存配置。
2. 核对小程序和公众号的身份匹配：系统现有流程通过 UnionID 匹配公众号关注者，再使用公众号 OpenID 发送。绑定平台后，历史账号缺失身份信息的情况应通过重新登录、身份绑定或同步补齐，不能假设旧记录自动更新。
3. 选择明确的试点教师和家长，预览相关资料和接收人，验证不可触达原因，不向全部用户试发。
4. 发布相关讲义或完成教案上传批次，验证产生正确事件与任务；批量资料按一次业务操作汇总，不逐文件重复推送。
5. 验证接口提交、微信发送回执、手机实际收到和点击打开，分别记录；请求成功或返回消息编号不等于用户已读。
6. 验证失败重试、权限变化和重复操作：可重试失败有明确入口；结果待确认的任务先查回执，不盲目重复发送。

### 按接收角色打开内容

| 消息 | 打开位置 | 登录和权限 |
| --- | --- | --- |
| 家长收到学生讲义通知 | 现有小程序通知详情及相关资料 | 登录后恢复通知，校验所绑定学生的课程与资料权限 |
| 教师收到内部教案通知 | 现有教师网页 `/teaching-plans?plan=...` | 登录后恢复教案，校验教师年级学科范围；批次内其他教案也有可发现入口 |

公众号绑定到开放平台与公众号关联小程序的跳转配置分别核对，以实际发送和打开结果验收。教师网页跳转沿用现有 HTTPS 来源配置，不把内部教案跳到学生页。当前批次教案链接定位第一份资料，需验证用户能找到该批其他资料；不完整时补批次入口。

扫码只作为身份补齐或实测配合步骤，按实际需要安排，不作为“重新绑定开放平台”的待办。首轮先验资料发布和教案上传通知，其他已有业务通知只做受影响回归。

## 七 后续组合课程

优先按“年级＋学科”提供聚合入口，再展示学期阶段及班型。例如进入 G4 Geography，看到对应阶段的课程，而非在总列表平铺所有课。

先以查询分组或组合引用现有 Course ID 实现，讲义、教案、练习仍归原课程；不要复制文件或借用已有 CourseFamily 改变共享目录关系。现有 CourseFamily 服务于同一学期阶段的不同班型共享目录，与跨学期组合含义不同。

后续明确四个阶段的构成、跨学年规则、是否需要自定义组合，以及组合是否参与排课、购买授权或下载，再决定是否增加持久化的组合实体。会议提到 11 月或下一阶段再规划，暂不承诺日期，不纳入本轮基础改动。

## 实施顺序与验收

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 第一阶段 | 目录定向同步、教案章节可选、教师列顺序 | 新 Unit 能同步指定班型，其他目录资料保留；有课程无章节可批量上传；表格滚动不遮挡 |
| 第二阶段 | 教案课程归组、统一标签筛选、文案精简；学年按确定口径接入 | 同一套筛选能找到课程和教案，历史未归类可查，返回恢复状态；年度规则不会隐藏旧资料或改变历史目录 |
| 第三阶段 | 移动端打包入口与电脑领取 | 指定角色从手机创建任务，电脑同账号领取完整包；任务参数跨登录保留，无权、失败、过期均可处理 |
| 第四阶段 | 公众号消息联调 | 指定接收人实际收到，点击打开正确内容；登录恢复、批次汇总、不可触达及重试验证完成 |
| 后续 | 组合课程 | 单独确定业务范围与方案后实施 |

公众号配置、模板和身份核对可以与前三阶段并行。开发验证使用隔离数据，试点通知和真实微信验收另行记录，不把模拟发送计为真实收件。

针对性检查：目录预览及执行覆盖单 Unit、整套、重复执行、并发修改、不同共享系列和失败重试；教案覆盖课程通用、指定章节、历史资料、权限和持久化；下载覆盖范围及包完整性、任务归属和登录恢复；公众号覆盖正确接收人、批次去重、回执和内容权限。界面改动检查实际渲染；不因方案文档新增而运行全量构建或测试。

## 需要确定的两项范围

1. 学年是资料版本归属，还是只表示校历上下文？本方案推荐需要年度差异时采用“学年版本＋通用资料”。
2. 小程序批量下载仅面向教师教务，还是也面向家长学生？本方案先按现有教师教务权限规划，若开放学生使用需补专门的授权和电脑领取流程。
