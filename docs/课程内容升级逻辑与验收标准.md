# 课程内容升级逻辑与验收标准

## 1. 目标与范围

本次升级面向管理端教师/教务和学生端，解决三件事：

1. 将面向学生的“学习资料”统一称为“课程讲义”，并把“模拟考试”从常规练习中区分出来；
2. 讲义支持上传 Word 文档，后台异步转换为 PDF 后供在线预览；不提供在线编辑；
3. 管理端可以检索讲义，并能为练习设置精确的截止时间、在截止后阻止提交并提醒学生。

本次不包含：Word 在线编辑、题目自动生成、考试监考/防切屏、对已提交答案的撤回或修改。

## 3. 统一业务模型

### 3.1 讲义

- 对外中文名称统一为“课程讲义”。
- 既有内部路由、权限码和套餐内容码保持不变：`/materials`、`canUploadHandout`、`handout`。这是纯展示名称调整，避免影响存量套餐和授权。
- `materials.material_type` 的新建值固定为 `课程讲义`；读取历史 `学习资料`、`资料`、`讲义` 时均映射展示为“课程讲义”。
- 讲义归属一个课程，因此学科取所属课程/学习空间的学科；上传人取 `ownerTeacherId`、`ownerTeacherName`；上传时间取 `materials.created_at`。
- 文件原件只用于受控下载；学生在线查看只使用转换后的 PDF 预览。Word、PPT、PDF 均不允许在线编辑。

### 3.2 练习与模拟考试

“模拟考试”不是讲义文件类别，而是练习的业务类型。原因是它需要复用题目、提交、得分、截止时间和批改链路。

新增字段 `assessmentType`：

| 值 | 管理端/学生端名称 | 含义 |
| --- | --- | --- |
| `practice` | 常规练习 | 课后练习；为历史数据和新建练习的默认值 |
| `mock_exam` | 模拟考试 | 以测评为目的的组卷；与常规练习独立筛选、标签、待办和统计 |

- 两类内容都从同一题库选题，计分方式、提交和批改规则一致。
- 模拟考试必须设置截止时间；常规练习可以不设置，设置后同样按限时规则执行。
- 不新增单独的“模拟考试资料”上传入口；如考试需要附件，后续另立需求，避免与讲义预览混淆。

## 4. 业务流程

### 4.1 上传与预览课程讲义

```text
教师/教务选择课程和文件
  → 服务端校验权限、扩展名、文件签名、单文件 ≤ 50MB
  → 保存原文件并创建讲义（状态：待转换）
  → 创建异步预览任务
  → LibreOffice 将 Word/PPT 转为 PDF；PDF 生成独立预览副本
  → 成功：可预览；失败：转换失败（保留原文件、展示原因、允许重试）
  → 学生仅在有套餐授权且讲义已发布时查看 PDF 预览
```

规则：

- 支持 `.pdf`、`.ppt`、`.pptx`、`.doc`、`.docx`，不改变已有文件兼容范围；仅新增 Word 能力不是收窄已有能力。
- 一个文件对应一条讲义。批量上传时以文件名去掉扩展名作为默认标题；单文件可手工改标题。
- 状态为“待转换/处理中”时预览按钮不可用并展示等待提示；“转换失败”展示失败原因和“重新生成预览”。
- Word 加密、损坏、超过 60 秒转换时失败；不得把原 Word 伪装成 PDF 返回。
- 编辑讲义元数据不替换文件；如需换文件，管理员删除旧讲义后重新上传，学生端立即只看已发布的新记录。

### 4.2 管理端检索课程讲义

筛选字段均为可选，多个条件取交集：

| 条件 | 前端交互 | API 参数 | 匹配规则 |
| --- | --- | --- | --- |
| 标题 | 搜索框，输入后回车或点击搜索 | `keyword` | 标题包含，忽略大小写 |
| 学科 | 下拉，仅显示启用学科 | `subject` | 讲义所属学习空间的学科完全匹配 |
| 上传人 | 可搜索下拉，值为人员 ID | `uploaderId` | `ownerTeacherId` 完全匹配 |
| 上传时间 | 日期范围，起止可单独填写 | `uploadedFrom`、`uploadedTo` | 包含边界；开始按 `00:00:00`，结束按 `23:59:59` |

接口为 `GET /api/materials`，保留数组响应，新增上述 query 参数；空条件仍返回当前账号权限范围内的全部讲义。先在服务端按权限过滤，再按筛选条件过滤，禁止通过筛选参数绕过老师的课程范围。

讲义列表列顺序：标题、学科、所属课程、上传人、上传时间、文件类型/大小、预览状态、发布状态、操作。空结果文案为“没有找到符合条件的课程讲义”，提供“清空筛选”。加载失败保留原有错误提示。

### 4.3 发布常规练习/模拟考试及截止

```text
教师选择“常规练习”或“模拟考试”
  → 选择负责范围内课程
  → 从同年级、同学期、同学科的启用题库选题
  → 设置标题、发布状态、截止时间
  → 服务端校验范围、题目、类型和时间
  → 发布后学生在已开通套餐下看到对应类型与截止时间
  → 截止前可提交；截止后服务端拒绝新提交
```

截止字段升级为 `deadlineAt`（ISO 8601，示例 `2026-08-27T20:00:00+08:00`）：

- 数据库存为 `DATETIME NULL`，业务时区统一为 `Asia/Shanghai`；`NULL` 表示不设截止。
- 新建或从草稿发布时，非空 `deadlineAt` 必须晚于服务器当前时间至少 5 分钟；编辑已发布内容不可把时间改到当前时间之前。
- 模拟考试：`deadlineAt` 必填。常规练习：可选。
- 学生端展示精确到分钟。未截止显示“截止于 MM月DD日 HH:mm”；截止后未提交显示“已截止”，入口置灰；已提交仍可查看自己的结果。
- `POST /api/student/submissions` 必须以服务端当前时间校验。若 `now >= deadlineAt`，不创建提交记录，按项目统一响应返回“本次练习已截止，无法提交”。客户端提示后刷新练习详情；不能只依赖小程序按钮置灰。
- 发布通知必须包含考试类型和截止时间。另增加一次截止提醒：在 `deadlineAt - 24h` 发送；若发布时间距离截止不足 24 小时，则不补发该提醒；提醒任务以“练习 ID + 学生 ID + reminder”幂等，练习停用、截止时间取消或学生已提交时不发送。

### 4.4 历史数据迁移

1. `materials.material_type` 中的历史名称统一回填为 `课程讲义`；对外读取继续兼容旧值。
2. 为 `homework_tasks` 新增 `assessment_type VARCHAR(16) NOT NULL DEFAULT 'practice'`，历史记录全部回填 `practice`。
3. 将 `homework_tasks.deadline DATE NULL` 扩展为 `deadline_at DATETIME NULL`。历史非空日期转换为当日 `23:59:59`（上海时区），以避免提前截止；保留旧字段仅用于一次性迁移，代码切换后删除旧字段。
4. `materials.created_at` 已存在，不新增列；补齐领域模型、MySQL load/snapshot 和 API 返回的 `createdAt`。
5. 增加索引：`materials (course_id, created_at)`、`materials (owner_teacher_id, created_at)`；学科通过已关联学习空间过滤，无需冗余存储。

## 5. 接口与数据契约

### 5.1 讲义列表

`GET /api/materials?keyword=&subject=&uploaderId=&uploadedFrom=2026-08-01&uploadedTo=2026-08-31`

讲义响应补充：

```json
{
  "id": "material-001",
  "title": "五年级英语阅读核心讲义",
  "type": "课程讲义",
  "subject": "英语",
  "ownerTeacherId": "teacher-001",
  "ownerTeacherName": "王老师",
  "createdAt": "2026-08-27 14:30:00",
  "previewStatus": "可预览"
}
```

### 5.2 新建、更新练习

`POST /api/homework`、`PUT /api/homework/{id}` 请求与响应新增：

```json
{
  "assessmentType": "mock_exam",
  "deadlineAt": "2026-08-27T20:00:00+08:00"
}
```

- 新建接口保留 `deadline` 仅作兼容读取；新客户端只提交 `deadlineAt`。
- 对历史客户端传入的 `deadline`，服务端临时转换为该日 `23:59:59`；两个字段同时传入时以 `deadlineAt` 为准，并记录兼容日志。
- 练习响应返回 `assessmentType`、`deadlineAt`、`submissionStatus`（学生端）和 `isOverdue`（由服务端计算）。
- 所有接口仍使用 `{ code, message, data }`，管理端操作人继续通过 `X-Operator-ID`、`X-Operator-Name` 透传。

## 6. 页面改造清单

### 管理端

- “课程内容”标签从“学习资料”改为“课程讲义”；上传、编辑、删除、空状态、套餐内容标签和工作台待办同步替换。
- 讲义页增加检索区：标题搜索、学科、上传人、上传时间范围、查询、重置；筛选值写入 URL query，刷新页面后保留。
- 上传弹窗标题为“上传课程讲义”，文件说明改为“支持 PDF、PPT、Word；上传后自动生成 PDF 预览；暂不支持在线编辑”。
- 练习创建/编辑弹窗增加“类型”单选。选择模拟考试时显示必填的日期时间选择器；常规练习可选择“不设截止”。不再使用自由文本输入截止时间。
- 练习列表增加“类型”“截止时间”“状态”列，并提供类型筛选；模拟考试用显著标签，避免老师误当日常练习发布。

### 学生小程序

- 首页、学习页、课程详情、预览页、收藏和成长记录中的“学习资料”均改为“课程讲义”。
- 讲义卡片显示文件类型、预览状态；转换中显示“讲义正在生成，请稍后再试”，失败显示“暂无法预览，请联系老师”。
- 常规练习与模拟考试分别显示“练习”“模拟考试”标签；待办按截止时间升序，模拟考试优先显示。
- 答题页以服务端 `isOverdue` 为最终准则：到期时停止提交并提示；网络恢复后重试也必须再次经过服务端截止校验。

## 7. 开发顺序与最小改动范围

1. 后端领域类型与数据库迁移：`Material.createdAt`、`Homework.assessmentType`、`Homework.deadlineAt`、查询对象和索引。
2. 仓储：加载/落库/快照、权限后过滤、截止校验、提醒任务幂等处理。
3. HTTP：绑定 query 与新请求字段，保持 `/api` 前缀和响应结构；更新 API 文档。
4. 管理端类型、接口调用、讲义检索、名称替换、日期时间控件、练习类型展示。
5. 小程序：名称替换、类型标签、截止状态、不可提交交互。
6. 文档转换运行环境与回归测试。不要把“模拟考试”另起一套题目或提交表，也不要重命名内部 `materials` 路由和 `handout` 权限码。

## 8. 验收标准

### 8.1 分类与命名

- [ ] 管理端、学生端、套餐、空状态和通知文案不再向普通用户展示“学习资料”，统一展示“课程讲义”。
- [ ] 既有讲义、套餐授权、`/api/materials` 路由和 `handout` 权限仍可正常访问。
- [ ] 创建常规练习默认保存为 `practice`；创建模拟考试保存为 `mock_exam`，两者在管理端和学生端均可辨识和筛选。

### 8.2 Word 上传与 PDF 预览

- [ ] 上传有效 `.doc`、`.docx` 后，列表先显示“待转换/处理中”，成功后生成独立 PDF 预览并可打开。
- [ ] Word 损坏、加密、超时和未安装 LibreOffice 时，明确显示失败原因，原文件仍可下载，管理员可重试。
- [ ] 讲义页面没有在线编辑入口；编辑弹窗不允许改写 Word/PDF 内容。
- [ ] 上传无效签名、非允许格式、空文件和超过 50MB 文件均被拒绝。

### 8.3 讲义检索

- [ ] 标题、学科、上传人、上传时间四种条件可单独和组合检索；边界日期均被包含。
- [ ] 结果只包含当前操作者有权限看到的课程讲义；修改 query 参数不能看到其他老师负责范围的内容。
- [ ] 列表准确显示学科、上传人、上传时间；无结果、加载中、接口失败都有对应提示。

### 8.4 截止时间与模拟考试

- [ ] 模拟考试不填截止时间不能发布；常规练习可不设截止。
- [ ] 管理端选择到分钟，服务端拒绝无效、过去或不足 5 分钟的截止时间。
- [ ] 截止前可提交；到达截止时间后，即便直接调用提交接口也不能新增提交记录。
- [ ] 已提交学生仍能看结果；未提交学生显示已截止；截止提醒不重复发送、不向已提交或已停用练习的学生发送。

### 8.5 自动化回归

- [ ] Go：Word 转换成功/失败/重试、讲义四条件组合筛选与权限隔离、`practice` 默认值、`mock_exam` 必填截止、到期提交被拒绝、提醒幂等。
- [ ] 管理端：构建通过；筛选、类型切换、日期时间校验、预览状态和文案替换的组件/端到端测试通过。
- [ ] 小程序：名称替换、模拟考试标签、到期置灰、服务端拒绝后的提示测试通过。
